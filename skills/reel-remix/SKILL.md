# reel-remix — найти референс-рилс и разобрать на раскадровку

## ⛔ Главные правила

- **Хештеги/ниша и язык контента — спрашивать у пользователя явно, не выбирать самому.** Даже похожая на предыдущий раз тема (напр. «ИИ») может требовать других хештегов или другого языка (русский vs иностранный) — пользователь однажды явно поправил язык хештегов посреди работы.
- **Не показывать результат через Artifact/веб-страницу.** Кадры и раскадровка показываются прямо в сессии Claude Code (через `Read` на файлы кадров) или открываются в Finder (`open -R <файл>`), не публикуются как HTML-артефакт.
- **Обязателен параметр `resultsType: "reels"`** при вызове `apify/instagram-hashtag-scraper`. Без него актор отдаёт «Recent»-ленту хештега вперемешку с картинками/каруселями и почти нулевыми лайками (проверено на практике — первый прогон без этого параметра дал 15 бесполезных объектов с 0 лайков).
- **У актора нет режима «топовые», только «последние».** Не пытаться искать параметр top/popular — его не существует. Сортировка по `videoPlayCount`/`likesCount` постфактум в локальном скрипте — единственный способ найти хорошие ролики.
- **Сначала маленький тест (лимит 5), потом полный прогон.** Ловит проблемы с параметрами дёшево (~$0.02), а не после полного платного прогона.
- **Референс выбирать по тематической релевантности, не только по цифрам** — это предположение/дефолт из практики этой сессии (не прямая правка пользователя, он не возражал), не жёсткое правило: самый залетевший ролик в общей выборке по хештегам может быть из смежной, но другой ниши (пример: топ по плеям — ролик про фоторедактирование, а нужен был про Claude Code конкретно — выбран был второй по цифрам, но точно в нише). Если сомнение — можно показать 2-3 кандидата пользователю и спросить, какой брать.

## ШАГ 1 — Discovery по хештегам

```bash
cd ~/reels-parser
node --env-file=.env fetch-hashtags.js "hashtag1,hashtag2,hashtag3" 5   # тест
```
Если `fetch-hashtags.js` ещё нет в проекте — создать по образцу `fetch-account.js`/`fetch-transcripts.js`, actor `apify~instagram-hashtag-scraper`, input `{ hashtags: [...], resultsLimit, resultsType: "reels" }`.

Проверить результат: реальные `type: "Video"` с ненулевыми `likesCount`/`videoPlayCount`? Если нет (в основном Image/Sidecar, 0 лайков) — параметр `resultsType` не выставлен или сбит, поправить и перезапустить тест.

После успешного теста — прогнать на нужном лимите (10-30 на хештег).

## ШАГ 2 — Выбор референса

Отсортировать по `videoPlayCount`/`videoViewCount` и/или `likesCount`. Выбрать не обязательно топ-1, а первый явно релевантный целевой нише пользователя (не просто широкой теме «ИИ» вообще).

## ШАГ 3 — Транскрипт (быстрая проверка)

```bash
echo '["<url выбранного рилса>"]' > output/ref-urls.json
node --env-file=.env fetch-transcripts.js output/ref-urls.json
```
Если транскрипт содержательный (реальная речь) — можно строить раскадровку по нему. Если пустой/бессмысленный (напр. «clap clap clap», звуковые эффекты) — это визуальный/текстовый формат без речи, переходить к ШАГ 4 обязательно.

## ШАГ 4 — Скачать видео и разобрать на кадры

Запустить актор `apify~instagram-reel-scraper` для того же URL с `includeDownloadedVideo: true` (напрямую через `fetch`+`runAndFetch` из `lib/apify.js`, не через `fetch-transcripts.js` — там нет этого параметра). В результате поле `downloadedVideo` — стабильная ссылка (не CDN-ссылка с истекающим токеном).

```bash
curl -sL "<downloadedVideo URL>" -o output/ref-video.mp4
mkdir -p output/ref-frames
ffmpeg -y -i output/ref-video.mp4 -vf "fps=1.5" output/ref-frames/frame-%02d.png
```
`fps=1.5` — стартовое значение для роликов до ~15 сек; для более длинных роликов уменьшить частоту (напр. `fps=0.5`), чтобы не наплодить лишних кадров.

Прочитать (`Read`) ключевые кадры — начало, каждую смену текста/сцены, конец — не все подряд, если ролик длинный.

## ШАГ 5 — Собрать раскадровку

Текстовое описание по кадрам: таймкод/номер кадра → что в кадре (план, текст на экране, действие) → сколько держится. Пример структуры (из реального разбора):

```
Кадр 1 (0-2с): селфи-план, текст-хук поверх видео: "<цитата>"
Кадр 2 (2-10с): чёрный фон, статичный заголовок держится, под ним сменяются N строк (~1.3с каждая):
  1. "..."
  2. "..."
  ...
```

Показать пользователю: раскадровку + отметить, что реально можно повторить без сложных съёмок (если формат позволяет — напр. только текстовые карточки на чёрном фоне + один короткий селфи-кадр).

## ШАГ 6 — Сгенерировать сценарий(и) с несколькими хуками

Не только разбор чужого референса — готовый сценарий под тему пользователя. Спросить (если не названо раньше в этой же сессии), какая конкретно история/идея/демо будет в его версии.

Собрать хуки из трёх источников:
1. **Структура и хук самого разобранного референса** (ШАГ 5) — стиль, регистр, длина.
2. **Все caption'ы из discovery-выборки** (ШАГ 1, не только выбранный референс) — прогнать по ним взглядом, поискать повторяющиеся словесные паттерны (не только у топ-1).
3. **`~/reels-parser/hooks-bank.md`** — накопленные за прошлые прогоны (в т.ч. из других ниш) подтверждённые формулы заголовков/хуков.

Выдать **2-4 варианта хука** (не один) под тему пользователя, с явной пометкой, из какого паттерна каждый вырос (структурный/словесный/формула). Затем — полный сценарий по структуре референса (кадр за кадром, как в ШАГ 5), но с содержанием под тему пользователя вместо содержания референса.

## ШАГ 7 — Обновить банк хуков

После показа сценария — дописать в `~/reels-parser/hooks-bank.md` (не переписывать старое, только дополнять):
- Референс этого прогона (ссылка, метрики, что за структурный/словесный паттерн)
- Если ниша уже встречалась — дополнить её раздел; если новая — создать `## Ниша: {название}`

## Финальный чеклист

- [ ] Хештеги и язык — подтверждены пользователем, не выбраны самостоятельно
- [ ] `resultsType: "reels"` использован в discovery-запросе
- [ ] Тест на малом лимите прошёл перед полным прогоном
- [ ] Референс выбран по релевантности нише, не только по цифрам
- [ ] Транскрипт проверен; если пустой — видео скачано и разобрано на кадры через ffmpeg
- [ ] Раскадровка показана прямо в сессии (Read/Finder), не через Artifact
- [ ] Сценарий сгенерирован под тему пользователя (не только разбор чужого), с 2-4 вариантами хука
- [ ] `hooks-bank.md` дополнен (не переписан) результатами этого прогона
