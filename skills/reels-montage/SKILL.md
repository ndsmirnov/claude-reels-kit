# Монтаж рилсов: войсовер + видео с телефона → готовый mp4

Скилл собран по итогам реальной работы над рилсами (сентябрь–октябрь 2026): что сработало, что автор забраковал, готовые скрипты.
Стартовые предпочтения ниже — это вкус первого автора; **в начале спроси пользователя, подходит ли ему** (§1), и подстраивайся.

Пути ниже — относительно папки скилла (`~/.claude/skills/reels-montage/`). Рабочая папка с venv — `$REELS_WORKDIR` (по умолчанию `~/reels-work`).

## 0. Что нужно на компьютере (проверь в первую очередь)
- **Mac.** Пути и шрифты в скриптах для macOS (`/System/Library/Fonts`, Apple Vision для поиска лиц, LUT — `/Library/Application Support/Blackmagic Design/...`).
  На Windows скрипты придётся адаптировать — скажи об этом пользователю.
- **ffmpeg + ffprobe** в PATH (`brew install ffmpeg`), Python 3, интернет для первой установки пакетов
  (`bash scripts/setup.sh` → venv в `$REELS_WORKDIR`: faster-whisper, scipy, pylibrb, pillow — несколько минут).
- **Node.js 20+** — для слоя графики на Remotion (`remotion/render.sh` сам сделает `npm install` при первом запуске).
- **Xcode Command Line Tools** (`xcode-select --install`) — чтобы собрать `scripts/faces` из `faces.swift` (раскладка текста мимо лиц).
- **DaVinci Resolve Studio** (платная) — ТОЛЬКО для классического пути через `resolve_build.py` (§2, §6). Внешние скрипты НЕ работают в бесплатной версии.
  После установки: Preferences → System → General → **External scripting using: Local**; DaVinci должен быть открыт.
  Формат «Конторка» (§3а) собирается без DaVinci: ffmpeg + Remotion.
- Необязательно: ключ fish.audio (`FISH_API_KEY`) для пробной озвучки `tts.sh`; Codex CLI с подпиской ChatGPT для `gen_image.sh`.

## 1. Начало работы с пользователем
1. Найди папку проекта (видео, голосовая запись `.m4a`/`.wav`). Если нет файла `CLAUDE.md` с описанием — предложи завести (шаблон — `ШАБЛОН_CLAUDE.md` в папке скилла: скопировать в папку рилса как `CLAUDE.md`) и задай 3–5 вопросов:
   цель рилса, стиль (референс-аккаунты), желаемая длина, нужна ли музыка (по умолчанию — без, см. §4), что нельзя показывать (люди, места).
2. Всё, что выяснили, записывай в `CLAUDE.md` проекта и в папку `монтаж/_данные/`, а не только в чат.
3. Большую задачу — сначала этапами и план показать. Пиши по-русски, коротко, без жаргона.
4. Никогда не удаляй и не перезаписывай то, что пользователь оставил или похвалил: каждая правка — **новая версия** (таймлайн/скрипт `vN` + файл `рилс_vN_….mp4`).
5. Рекомендуемый порядок согласования нового рилса (стоп ✋ = показать пользователю и дождаться «да»):
   0 тема → 1 хук (3 варианта) ✋ → 2 сценарий ✋ → 3 раскадровка с гэгами ✋ (до генерации картинок) → 4 генерация и подбор кадров ✋ → 5 черновик ✋ → 6 финал → 7 замер статистики через 48 ч.
   Первые несколько рилсов — все ✋ обязательны.

## 2. Процесс (по шагам, классический путь через DaVinci)
1. `bash scripts/setup.sh` → venv с ffmpeg и библиотеками; `export FFMPEG=$REELS_WORKDIR/ffmpeg` для `bands.py`.
2. Расшифровка голоса: `python scripts/transcribe.py голос.m4a words.json` (whisper medium, по словам). Спорные слова переслушай отдельными кусками
   и уточни у пользователя (модель путает имена и повторы дублей).
3. Нарезка голоса: по расшифровке найди чистые фразы последних дублей → `voice_cut.py` (`take_start`, `take_end`, `exclude` для неудачных дублей,
   `tempo 1.15` без изменения высоты, `gain_db 0` для сырой версии) → wav + `keep.json`.
4. Голос к «студийной» громкости: `python scripts/vproc.py сырой.wav готовый.wav 6 -3 2.5` (→ −14.2 LUFS, пик −0.8 dBFS), затем −0.6 дБ запаса.
5. Субтитры по одному слову из `words.json` → маппинг через `keep.json` (время/темп) → `chunks.json`. Фразы чёрных вставок — отдельные чанки.
6. План кадров `shots.json`: склейка на границах чанков. Для выбора кадров делай контакт-листы клипов (1 кадр на клип, по 35 клипов на лист) и смотри их;
   подозрительный клип смотри в 4–6 точках (в одном клипе бывают разные люди и смысл).
7. HDR-клипы iPhone (`color_trc arib-std-b67` в `ffmpeg -i`) → SDR-копии `scripts/hlg_to_sdr.sh` ДО сборки (§8).
8. Субтитры: `python scripts/subs.py chunks.json out.mov --ffmpeg … --total … --card "последняя фраза" --card-start … --card-times … --card-bold N`
   → ProRes 4444 с прозрачностью (по умолчанию Montserrat SemiBold).
9. Звук на вставках: `vfx.py phone` по окнам вставок (json `[{start,end,text,step}]`), при музыке — `vfx.py muffle`.
10. Сборка и рендер: `source scripts/renv.sh && python scripts/resolve_build.py config.json` (образец — `examples/example_config.json`).
11. Проверка: `python scripts/bands.py рендер.mp4` (LUFS, пик), контакт-лист кадров рендера, самопроверка (§5). Только потом отчёт; готовые mp4 копируй в `~/Downloads`.

## 3. Рецепт «быстрые кадры + чёрные вставки + звук как по старому телефону»
- **Монтаж:** кадр ~0.6 с, склейка на каждое слово/фразу, длинные кадры (>0.95 с) режутся джамп-катом (другой момент того же клипа). Клипы не ускорять.
  Движение на каждом кадре: push 1.0→1.14, pull 1.18→1.02, jump 1.26→1.34, punch 1.45→1.16 + вспышка. Кадры подбирай по смыслу слов фразы.
- **Вставки:** 5–7 ключевых фраз (тревожные и переломные) — вместо кадра **чёрный экран** со всей фразой (клип «BLACK» в config:
  `ffmpeg -f lavfi -i color=c=black:s=1080x1920:r=30:d=6 -c:v libx264 -pix_fmt yuv420p black.mp4`), эффект push.
- **Звук на вставках:** `vfx.py phone` — голос 400–3200 Гц, лёгкое насыщение и шипение, −2 дБ (эффект «по старому телефону»; популярный приём).
  Если просят «эхо» или «печатную машинку» — `vfx.py echo` / `vfx.py type` (+ в чанке `"type": true, "step": 0.045` для печати по буквам).
- **Фирменный шрифт — Montserrat во всём монтаже** (файлы `fonts/`, лицензия OFL). Субтитры SemiBold, заголовки/призыв Bold, карточка Medium+ExtraBold, Remotion — тот же Montserrat.
  Другой шрифт — `subs.py --font <путь.ttf>` (например, SF Mono `/System/Library/Fonts/SFNSMono.ttf --size 46 --y 990`), если пользователь попросит.
- **Стандарт экранного текста** — применяется автоматически `scripts/textnorm.py` в `subs.py` и `remotion/render.sh`: (1) без «ё» → «е»; (2) деньги — `12,000 ₽`
  (запятая-разделитель тысяч, знак рубля через пробел); ₽ ставится только при явных «руб/рублей/₽» — «12 тыс. за выпуск» без рубля станет «12,000», поэтому денежные суммы
  в тексте сразу пиши с ₽ («12 тыс. ₽»). Нормализация меняет число слов («12 000 руб.» → «12,000 ₽») — `--card-times` считать по нормализованной фразе.
  (3) Заголовки-хуки — триггерные (боль/деньги/провокация/цифра), не описательные; формулировку прогонять на конкретной теме ролика вместе с пользователем.
  Если пользователю этот стандарт не нужен — поправь `textnorm.py`.

### 3а. Формат «Конторка» — ИИ-кадры-шаржи + твои кадры (без DaVinci)

Тренд «Конторка»: история рассказывается кадрами нарочито кривой 3D-графики «как в старой игре» вперемешку с живыми кадрами автора.
Образец сборки — `scripts/build_example.py` (сегменты базы, выравнивание цвета, props графики). Новый рилс начинать копией и менять только SEG/props/chunks.

Пример удачной структуры (~40 с, 11 битов): К+П хук (ИИ-персонаж с деньгами сверху, автор снизу) → К гэг-кадр, punch на ударном слове → Я активный кадр по теме
→ К персонаж-двойник «X AI», punch → К+П ИИ-кадр сверху, снизу 2–3 коротких перебивки → Я запись экрана/работа → Я путешествие/люди → К+П абсурдный гэг
→ К бытовое сравнение (утрированно бедно/смешно) → Я эффектный кадр → финал: автор в кадре. Конторки ≈ 40 %, одинаковые типы подряд не стоят, клипы не повторяются.
(К — ИИ-кадр на весь экран, К+П — ИИ-кадр сверху + перебивка снизу, Я — автор на весь экран.)

**Сценарий и юмор**
- Стиль — юморной шарж: реальная боль/цифра → дерзкое действие → абсурдный поворот с персонажем по имени («Имя AI») → бытовое сравнение → коллбэк. Цифры реалистичные, гипербола в хуке допустима.
- AIDA: цену продукта/подписки не называть ни голосом, ни картинкой; гэг сравнения — на дешевизну, не на роскошь (пир читается «подписка дорогая»).
  Призыв — «пиши слово X — расскажу, как…».
- Оговорки «что ИИ пока не умеет» без просьбы пользователя не добавлять. Программы — с иронией.
- Два файла: `*-голос.txt` (фонетика: «Клод Код», «нэйросэть», «Эй Ай», числа словами) и `*-субтитры.txt`. Голос «Конторки» читает ~1,7 слова/с → 40 с ≈ 60–65 слов;
  длину мерить пробной озвучкой `tts.sh` (бесплатная модель).

**Кадры**
- Сначала уже сгенерированные кадры из прошлых рилсов, новые — только где старые не подходят; гэги — абсурд, не иллюстрация. Лучше больше картинок, чем лишняя генерация.
- Перебивки с автором — активные, с людьми и движением (общение, путешествие, игра, образ), не «сижу один за компом / лежу».
  Полезно завести у себя банк лучших кадров (список файлов с пометками) и брать оттуда.
- **Присланное «на потом» — в банк, не в текущий ролик**: в ролик только то, что пользователь прямо назвал «в этот»; двусмысленно — короткий вопрос.
- Не брать: где автор говорит в камеру под чужой голос (губы ≠ озвучка), где он «плохо выглядит», вейп/алкоголь, полуголые селфи. Смотреть ВЕСЬ участок клипа, не превью.
- Горизонтальные видео (подкаст, интервью) — только общий план с людьми в кадре; если в кадре один гость — подобрать таймкод, где видны оба.
- Кадр с действием всем телом — на весь экран (тип «Я»), не кропом в диптих. Финал — эффектный кадр с автором; долгий однообразный кадр (поездка за рулем) — 1,5–4 с максимум.

**Вёрстка**
- Диптих без размытых рамок: горизонтальное видео 16:9 снизу полосой 1080×608 (`BOT`, вертикальный клип — `BOTV` с окном по лицу), ИИ-кадр сверху `half` + `"h": 1312` (+ `py`).
- Лица не резать ни автору, ни персонажам: punch/to с точкой `fx/fy` на лицо, мягкий `pz` 1.12–1.25, если в кадре вторая важная деталь.
- Цвет кадров автора выравнивать перед склейкой (`normalize` в build_example.py: Y к медиане, U/V к нейтрали наполовину, предел ±7).
- Субтитры не позже речи: чанки −0,2 с, после паузы — `silence_end − 0,08`.

**Сборка (порядок, без исключений)**
1. `build_vN.py` → база: сегменты по сетке кадров Remotion (`nf = round(e*30) − round(s*30)`, `-frames:v nf`); HDR-клипы → `hlg_to_sdr.sh` (только `arib-std-b67`).
2. `remotion/render.sh props.json <АБСОЛЮТНЫЙ путь>/графика.mov` (только если менялись props; иначе брать графику прошлой версии — props сравнить `diff`).
3. `subs.py chunks.json … --avoid-video база.mp4 --avoid-props props.json`.
4. Склейка в 2 шага: база+графика → `шаг1.mp4`; `шаг1`+сабы → `видео.mp4` (3 входа за раз теряли кадры графики).
5. Звук отдельно: голос (`afade` 0,3 с qsin на последнем слове, `apad` до конца) + музыка −21 dB с подъемом после голоса (`aeval` по сэмплам, не `volume eval=frame` — щелчки)
   и гашением последние 0,6 с → `loudnorm` −14 → `звук.wav`; мукс `-c:v copy`. Хвост после голоса ≥ 1,3 с. Музыку — только ту, на которую у пользователя есть права.
6. `scripts/endcheck.sh черновик.mp4` — спектрограмма конца глазами (нет щелчков/стены/провала) + чёрные провалы (должно быть пусто; есть → пересклеить шаг 4) + лист кадров из середины каждого бита глазами.
7. Только после этого — пользователю; про звук писать «спектр чистый, проверь на слух», не «исправлено».

**Монтажный лист «Конторки»:** бит 1,2–2 с по разметке слов озвучки; типы: К / К+П (2–3 перебивки снизу по 0,7–1,5 с) / Я; ~40 % Конторки, без двух одинаковых типов подряд,
клипы не повторяются; лист показывать пользователю таблицей «бит → текст → кадр» до сборки. 6–8 ИИ-кадров на рилс, каждый — заранее придуманный АБСУРДНЫЙ гэг
(`gen_image.sh kontorka` уже добавляет «шарж/гротеск»). Движение у каждого кадра своё: `move` in/out/pan-l/pan-r/to(fx,fy) + `wobble`, `punch` на ударном слове.

**Грабли окружения:** venv — `scripts/setup.sh`; `transcribe.py` декодирует аудио сам через ffmpeg; `render.sh` относительный путь пишет в `remotion/` — давай абсолютный;
длинные склейки — фоном с запасом по времени (≥ 40 мин).
- **Графика поверх видео:** (1) ничего не моргает — Remotion рендерить в 1 поток (`--concurrency=1`, при 2 скрин пропадал на одиночных кадрах), тезисы подряд меняются без зазора;
  проверка — альфа по кадрам (`alphaextract,signalstats` → нет одиночных провалов); (2) логотипы — сами по себе с мягкой тенью, БЕЗ белой подложки, крупно (высота 240 px, оценка 110 px ExtraBold);
  (2б) у всего текста без плашки — плотная тень под шрифтом, видна и на светлом фоне; (2в) вставки из реальной съёмки — ВСЕГДА видео-кусок (`insert` с `.mov/.mp4` + `from`), не стоп-кадр:
  стоп-кадр из видео выглядит мёртво; картинка-вставка — только ИИ-генерация. Проверка: разница соседних кадров внутри вставки > 0;
  (3) скрины и картинки не закрывают лицо: скрин — в нижней части кадра, логотип — над головой/в пустой зоне; проверять кадрами глазами.
- **Субтитры:** по одному слову, маленькие (~46 px на кадре 1080×1920), белые, по центру кадра; слова ≤2 букв клей к следующему.
  Финальная карточка: чёрный экран, последняя фраза печатается синхронно с голосом, ключевое слово жирным.
- **Голос:** −14.2 LUFS, пик ≈ −0.8 dBFS; итоговый файл −14.5…−15 LUFS, пик ≤ −0.7 (запас под сжатие Instagram).
- **Цвет:** нейтрально-тёплый: CDL на все клипы, кроме чёрного, `slope 1.03 1.0 0.97`, `power 0.96`; мягче — `1.05 1.0 0.95, power 1.06, sat 0.93`. R и B связаны, G не трогать.
  Контроль: `python scripts/cstat.py рендер.mp4` (ориентир: R−B 0…0.09, sat 0.21–0.36, Y 0.32–0.44).
- **Музыка:** по умолчанию **без музыки** — пользователь накладывает трендовый звук в Instagram (понижает до 10–20 %). Если пришлёт свой трек —
  подгони до −25…−26 LUFS при голосе −14.2, подрежь, fade out, на чёрных вставках приглушай (`vfx.py muffle`).
  Опыт автора: синтезированная музыка (numpy) звучит «игрушечно» и не понравилась три раза подряд — её не предлагай. Готовые бесплатные треки
  (Mixkit, Pixabay, YouTube Audio Library) можно показать пользователю кандидатами. Популярные коммерческие треки из интернета не скачивай (авторские права).
- **Варианты:** давай 2–3 версии (например, мягкий и заметный цвет; быстрый и более медленный монтаж) — пользователь выбирает на глаз.

## 4. Что не понравилось автору (подумай, прежде чем предлагать)
Крупные цифры/слова поверх кадра, цветные плашки под словами, радужные градиентные вставки, эхо на вставках, тёмный teal&orange LUT с виньеткой,
плёночный фильтр с зерном, крупный жирный капс в субтитрах, синтезированная музыка. Графику и моушн не придумывай сама: попроси референс (видео/скриншот).

## 5. ⛔ Самопроверка перед показом рилса
Смотри контакт-лист рендера (`ffmpeg -i рендер.mp4 -vf "fps=1/2,scale=144:256,tile=8x2" -frames:v 1 -strict unofficial лист.jpg`):
1. Везде ли в кадре с человеком — сам пользователь? (В клипах бывают друзья, коллеги, прохожие.)
2. Нет ли кадров, где человек выглядит нелестно или которые он не хотел бы показывать (бельё, чужие вшитые надписи, лишние люди)?
3. Нет ли чёрных полос от горизонтальных клипов в вертикальном кадре?
4. `bands.py`: LUFS ≈ −14…−15, пик ≤ −0.7 dBFS.
5. Формат «Конторка» — обязательно пункты 6–7 блока «Сборка» выше: `endcheck.sh` (спектр конца + чёрные провалы) и лист кадров по битам; без этого черновик не показывать.
6. Каждую правку пользователя — сразу в `CLAUDE.md` проекта (обобщённо); повтор той же правки = ошибка процесса.
Честно скажи, что на слух (музыка, эффект) и в движении ты не проверяла, и что проверено цифрами/кадрами. Сомневаешься, есть ли в кадре пользователь — не бери этот кадр.
Если пользователь говорит «не так» — исправь все похожие места и запиши урок в `CLAUDE.md` проекта.

## 6. DaVinci Resolve Studio — рецепты API

- Внешние скрипты работают только в **Studio** (в бесплатной — только Workspace → Scripts). Окружение: `scripts/renv.sh`.
- DaVinci должен быть запущен. Импорт MOV — **по одному файлу** (пакетный ImportMedia однажды завис на 5 мин).
- iPhone-повороты DaVinci понимает сам (клипы 1080×1920).
- Настройки проекта: 1080×1920, 30 fps, `colorScienceMode=davinciYRGBColorManagedv2`,
  `inputDRT/outputDRT=DaVinci`, `timelineWorkingLuminanceMode=SDR 100` (иначе оригинальные HLG пересвечены).
- `AppendToTimeline([{mediaPoolItem,startFrame,endFrame,recordFrame,trackIndex,mediaType}])`: endFrame — исключающий;
  mediaType 1 = только видео (звук клипов не нужен), 2 = только аудио. В занятое место не вставит.
- Титры через `InsertFusionTitleIntoTimeline` непригодны (всегда V1, 5 с, не обрезать) → субтитры отдельным
  ProRes 4444 alpha-клипом на V2 (V3, если на V2 что-то ещё).
- Картинки (png) через Append игнорируют endFrame (5 с) → делай из них видеоклип нужной длины.
- Зумы: `item.AddFusionComp()` → Transform + `BezierSpline` ключи; кадры композиции начинаются с 0
  (`COMPN_RenderStart/End`). Вспышка: BrightnessContrast.Gain. **После обрыва сессии Fusion-композиции старых
  таймлайнов могут пропасть** (GetFusionCompCount()=0) — готовые mp4 целы, при перерендере зумы восстанавливать.
- Цвет на клип: `item.SetCDL({"NodeIndex":"1","Slope":"r g b","Offset":"o o o","Power":"p p p","Saturation":"s"})`.
- LUT: `.cube` класть в СИСТЕМНУЮ папку `/Library/Application Support/Blackmagic Design/DaVinci Resolve/LUT/<Папка>/`
  (латиница!), затем `project.RefreshLUTList()` и `item.SetLUT(1,"<Папка>/<file>.cube")`. Пользовательская ~/Library папка не сканируется.
- `SetSpeed` сохраняет длину клипа и проматывает больше исходника (клипы лучше не ускорять).
- Дубликат таймлайна: `timeline.DuplicateTimeline(name)` — сохраняет цвет; замена клипа = DeleteClips + Append в тот же промежуток.
- Рендер: `SetCurrentRenderFormatAndCodec("mp4","H264")`, `SetRenderSettings({SelectAllFrames, TargetDir, CustomName})`,
  `AddRenderJob`, `StartRendering`, ждать `IsRenderingInProgress()`.
- Кэш: `perfRenderCacheMode=smart`, `perfAutoRenderCacheFuEffect=1`.


## 7. Голос — технические детали

- Огибающая 10 мс, порог речи −48 дБ, паддинг −35 мс / +50 мс, слияние щелей <70 мс, фейды 6 мс на стыках.
- Темп: `pylibrb` RubberBandStretcher(OFFLINE|ENGINE_FINER|FORMANT_PRESERVED), подавать блоками по 8192 сэмплов
  (`set_max_process_size`), иначе обрабатывает только кусок.
- Громкость: highpass 60 Гц, +~9 дБ, alimiter limit 0.89 → ≈ −17.5 LUFS, пики ≈ −4 dBFS. Проверь одиночные выбросы пиков.


## 8. Цвет — технические рецепты

1. **HDR-клипы iPhone (HLG)**: НЕ тонмаппить в DaVinci. Перекодировать в SDR, трактуя HLG как BT.709-гамму
   (HLG обратно совместим) с переводом гаммы цветов 2020→709 — `scripts/hlg_to_sdr.sh`. Число кадров совпадает с оригиналом.
   Так кадры выглядят «как на телефоне». Тонмаппинги (DaVinci DRT, hable, mobius) дают серость/кислотный синий.
2. SDR-клипы (обычные iPhone) слегка нейтрализовать, если слишком оранжевые: CDL с **связанными** R/B
   (slope R=k, G=1, B=1/k) — только ось тепло↔холод, зелёный не трогать, иначе лица зеленеют.
3. Синий неон (LED-подсветка) — точечно: slope `1.2 1 0.83`, saturation ~0.72.
4. Контроль: по кадрам мерить Y, p2/p98, насыщенность, R−B; ориентир популярных сторителлинг-аккаунтов: R−B 0.01–0.04, sat 0.21–0.29,
   света ≤0.84, чёрный 0.03–0.08. Но финальное решение — глазами по контакт-листу.


## 9. Плавное воспроизведение в DaVinci

`scripts/proxies.sh` — ProRes Proxy 540×960, `-r 30`, теги цвета как у оригинала; затем
`clip.LinkProxyMedia(path)` и `project.SetSetting("perfProxyMediaMode","1")`. Проверь, что число кадров прокси = оригиналу.
